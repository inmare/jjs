영상(프레임) 감시 실험 리포트

이 페이지는 같은 프레임(이미지)에 대해 여러 가지로 AI를 돌렸을 때 걸리는 시간·GPU·토큰(입력 길이 대략치)을 나란히 보여 줍니다. 용어가 낯설면 아래 「용어 설명」을 먼저 펼쳐 보세요. 표·제목에 마우스를 올리면(밑줄 점선) 짧은 설명이 뜨는 곳이 있습니다.

용어 설명 (접기/펼치기)
Qwen / Qwen-only
이 실험의 큰 VLM(비전+언어 모델). Qwen-only는 전체 화면을 작게 맞춘 이미지 1장만 넣어 물어본 경우입니다.
YOLO + Qwen (YOLO+Qwen)
YOLO는 사진 안의 물체(사람, 차 등)를 빠르게 찾는 작은 AI입니다. 찾은 부분을 잘라낸 그림(크롭)까지 같이 VLM에 넣어 답을 요청한 파이프라인입니다. 그림 장수가 늘어 시간·토큰이 Qwen-only보다 클 수 있습니다.
Smol (SmolVLM)
Qwen보다 가벼운 작은 VLM. 먼저 짧은 판단·요약을 하고, 필요하면 Qwen을 부르는 2단계에서 쓰입니다.
YOLO∥Smol → Qwen
∥(병렬)은 YOLO와 Smol을 동시에 돌린 뒤, 합쳐서 Qwen에 넘기는 실험 줄입니다. 합쳐진 벽시계 시간은 표에 wall로 적힌 구간이 있습니다.
2단계 (Smol → Qwen)
1단에서 Smol(또는 YOLO만으로 짠 규칙)으로 요약·위험도를 보고, 조건이 맞으면 2단 Qwen을 건너뛸 수 있습니다.
입력 토큰 (prompt_tokens, 표에서는 p/c/t)
서버가 알려 주는 입력 길이 대략치입니다. p=입력, c=생성(답), t=합계. 이미지는 토큰으로 환산되어 포함될 수 있습니다.
VLM 생략(0) / «비전~N»
프레임이 이전과 비슷해 이번엔 VLM에 요청을 안 보낸 경우, p/c/t는 0/0/0으로 보입니다. 뒤의 «비전~숫자»는 보냈을 때의 비전 토큰(규칙으로 추정)이며, 실제 API에 청구된 값이 아닙니다.
GPU (MiB) / util%
그래픽 메모리 사용량(메비바이트)과 GPU 바쁨 정도(%)입니다. 전체 그래픽 카드 기준이라, 다른 프로그램이 쓰는 양이 합쳐질 수 있습니다.
Python RSS
이 실험을 돌리는 Python 프로세스가 쓰는 일반 메모리(RAM)입니다. llama-server는 별도 프로세스일 수 있습니다.
프레임 게이트 / MSE / YOLO 서명
연속 사진이 이전과 거의 같으면 VLM을 다시 안 돌리기 위한 절약입니다. MSE는 흑백 썸네일끼리 얼마나 닮았는지(작을수록 닮음). YOLO 서명은 “몇 개 찾았는지+어떤 종류인지”를 짧은 글로 비교하며, 위치는 보지 않습니다.
구간·게이트 (ms)
읽기·MSE·YOLO·Qwen 호출마다 걸린 밀리초를 나누어 쓴 줄입니다. 스킵한 프레임은 일부가 0에 가깝게 보일 수 있습니다.

GPU·아래 토큰 수는 서버/드라이버가 보내온 값입니다. GPU는 nvidia-smi의 카드 전체이며, Python의 python_rss_mb는 이 스크립트만의 RAM입니다.

시간: YOLO∥Smol→Qwen 행 = YOLO와 Smol을 동시에 돌린 뒤 이어서 Qwen을 호출한 흐름(벽시계 wall 포함)입니다. 2단계에서 risk=low이면 Qwen을 생략한 실행도 있습니다. 벤치의 YOLO+Qwen은 크롭 이미지 여러 장이므로 다른 줄과 토큰·시간을 직접 비교하기 어려울 수 있습니다.

응답까지 걸린 시간(초)

짧을수록 빠름. 시나리오마다 보내는 그림 수가 달라 직접만 비교는 어려울 수 있음

입력 토큰 수 (서버 보고)

p/c/t = 프롬프트(입력) / 생성(답) / 합계 — 여기서 막대는 주로 prompt 쪽

추론 직후 GPU 메모리 (MiB)
